# Clip：轻量、键盘顺手的本地剪贴板库

Clip 把查找、选择、编辑和复制放在一个原生 Mac 窗口里。方向键移动，Shift 扩选，Return 复制；常用内容可以置顶、收藏和直接修改。

## 为什么考虑替换 Deck

如果主要需要本机历史检索、片段整理和复用，Clip 提供更小的应用体积和直接的键盘操作。若依赖 Deck 的 AI、同步或插件生态，当前 Clip 不能完整替代这些能力。

| 项目 | Clip build 26 | Deck 1.4.5 |
|---|---|---|
| 本机安装占用（du，约数） | 3.3 MB | 60 MB |
| 核心方向 | 本地历史、筛选、编辑、多选复制 | 剪贴板工作流，另有 AI、同步与插件生态 |
| 键盘 | 方向键、Shift 扩选、Return、Tab；文字编辑保留光标语义 | 本轮未做完整按键对等测试 |
| 跨设备、AI、插件 | 当前不提供 | 官方产品提供相关能力，具体条件见官方说明 |

竞品功能来源：[Deck 官网](https://deckclip.app/)、[官方仓库](https://github.com/yuzeguitarist/Deck)、[Deck AI](https://deckclip.app/showcase/deck-ai)、[插件目录](https://apps.deckclip.app/)。本机观察日期：2026-09-08。

## 已测到的内存改善：Clip 自己的前后对比

同一台 Apple M4、同一份历史与图片、release 编译、同一操作脚本，使用 physical footprint，单位 MiB。旧版 9c340bf，新版 4f2e245。此表不是与 Deck 的对比。

| 场景 | 优化前 | 优化后 |
|---|---:|---:|
| 主窗口 | 51.4 | 51.3 |
| 连续浏览图片页 | 275.5 | 117.3 |
| 浏览图片后关闭窗口 | 275.5 | 106.7 |
| 重新打开 | 277.3 | 125.3 |

图片浏览场景下降约 57%，关闭后下降约 61%。首次打开的基础占用没有明显改善。缩略图按尺寸解码、预览缓存有上限、隐藏窗口释放界面；原始图片与未保存草稿仍保留。

## 还不能宣称什么

一次 30 秒空闲观察：Clip 主窗口约 68–71 MB，Deck 后台约 85 MB；单核 CPU 平均约 0.33% 与 0.07%。窗口状态和历史不相同，所以不能据此声称全面胜出。CPU 本轮反而是 Deck 更低。启动、搜索、粘贴的相同负载延迟尚未测量，不宣传“比 Deck 快几倍”。

演示视频使用隔离的 13 条虚构数据，真实 build 26 窗口，操作片段保持原速，剪去等待。它展示交互，不是计时基准。生产数据不用于公开素材。
