# Clip / PastePal / Maccy：本机情景观察

2026-09-08，Apple M4、macOS 27.0。每个阶段观察 30 秒，内存为主进程 **physical footprint（MiB）**，不是 RSS、安装包大小或全系统用量。以下均为阶段结束值。

| 应用 | 纯文本窗口 | 纯文本收起 | 20 张图片界面 | 图片浏览后收起 |
|---|---:|---:|---:|---:|
| Clip build 26 | 48.5 | 47.5 | 95.5 | 94.7 |
| PastePal 2.21.1 | 77.8 | 78.4 | 271.9 | 260.1 |
| Maccy 2.7.1 | 50.4 | 55.1 | 409.8 | 444.1 |

**这次图片情景下，Clip 内存较低；纯文本下与 Maccy 接近。** 不能把这张表解读为所有任务下的性能排名。

| 后台 CPU，单核平均 | 纯文本收起后 | 图片浏览收起后 |
|---|---:|---:|
| Clip | 0.079% | 0.073% |
| PastePal | 0.029% | 0.124% |
| Maccy | 0.018% | 0.078% |

空闲 CPU 都很低，单轮小数差异不宜当成排名。这里没有同负载启动、搜索或粘贴延迟，**不宣称 Clip 比竞品快几倍**。

## 条件与边界

- 三款使用相同的 100 条虚构短文本和 20 张程序生成的 2048×2048 PNG。Clip 文本预置在隔离库，另外两款逐条录入并另保留 2 条初始记录。纯文本表是重新启动后；图片表是连续录入后。
- Clip 与 PastePal 显示图片网格，Maccy 显示列表与图片预览。窗口尺寸、缩略图数量和 UI 形态不同，未做像素级渲染对齐。
- PastePal 在收起主窗口后还须隐藏侧栏。Maccy 切换两次预览后收起面板。Clip 滚动图片网格后关窗。
- 图片数据送入阶段 Clip 和 Maccy 曾同时运行；没有把这个阶段的 CPU 当作吞吐性能结论。阶段采样属于轻载桌面环境中的探索性观察，未进行多轮统计。
- PastePal 连续录入文本后的窗口占用为 94.9 MiB，重启后为 77.8 MiB，说明缓存与使用阶段会影响结果。
- 测量用 `proc_pid_rusage`；本机时间字段按 `mach_timebase_info` 比例转换，并与 `ps TIME` 核对。没有使用自动化工具的调用耗时冒充应用响应时间。
- 本页只覆盖上述三款。没有 Paste、CleanClip 或 Deck 的同状态完整排名，也不把缺测当作 Clip 胜出。
